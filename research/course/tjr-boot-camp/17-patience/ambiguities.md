# Lesson 17 — Ambiguities (Patience)

Vague points and undefined thresholds a human must resolve before coding rules.

## Undefined thresholds
1. **Entry checklist timeframes [03:36–03:49].** The sequence liquidity sweep → BOS → FVG fill → reaction → entry has no timeframe attached to any step. Cannot code the gate without pairing to a technical lesson that specifies HTF bias tf and execution tf.
2. **"Reaction" is unquantified [03:47].** What constitutes a valid reaction (rejection wick? engulfing? displacement?) is not defined here.
3. **Confirmation candles [08:18].** "One or two candlesticks" — soft, and no entry timeframe. "Volume" and "volatility" confirmation are named but never thresholded.
4. **High-probability / confluence minimum [03:00–03:16].** He rejects "one confluence" entries but never states the minimum number of confluences or a score cutoff.
5. **News blackout [06:15].** "If there's news you shouldn't even trade" — no window (minutes before/after), no impact tier, no instrument list. Needs a dedicated news lesson.
6. **"One trade a day" [10:04].** Stated as personal cadence + advice. Ambiguous whether it is a hard max_trades_per_day cap or an aspiration. Treated as configurable in proposed-rules.
